# Privé — Next.js site

Next.js 16 (App Router) + React 19 + framer-motion. No Framer runtime: every section is a native component.

```bash
npm install
npm run dev
```

## Pages

| Route | Page |
|---|---|
| `/` | Home |
| `/about` | About |
| `/work/huddle` | Huddle |
| `/work/wider-perspective` | Wider Perspective |
| `/governing-charter` | Governing Charter |
| `/contact` | Contact (WhatsApp, email, socials) — copy in `content/contact.ts` |
| `/privacy-policy` | Privacy Policy — text in `content/privacy.ts` |

Qualification, FAQ and Operating Philosophy are popups.
`/governing-charter` reads its 16 sections from `content/charter.ts`.

## Scrolling and header

- Lenis smooth scrolling runs site-wide (`components/site/SmoothScroll.tsx`), off for reduced-motion users.
- The header is pinned to the top. It is see-through over dark heroes and gets a light background once page content is under it. To let it scroll away again, set `STICKY_HEADER = false` in `components/site/Header.tsx`.
- A floating "Apply for Membership" button (bottom right) is on every page except the form itself (`components/site/ApplyButton.tsx`).

## Editing content (no layout code needed)

- `content/site.ts` — menu, hero images, Why, Qualification, FAQ, Operating Philosophy, footer
- `content/events.ts` — **every session**. The When carousel and the month calendar both read this one list
- `content/practices.ts` — the What section: speakers, four functions, leaders, pricing
- `content/previously.ts` — Previously at Privé cards and their photo galleries
- `content/pages.ts` — About, Huddle, Wider Perspective copy and images

Image fields left as `""` show a neutral block (labelled in dev) until you paste a link.

## Black overlay on heroes

One setting in `app/globals.css`: `--hero-overlay` (black gradient, 0% at the top to 45% at the bottom).

## Fonts

Inter is bundled. Mencken Std (regular + bold) and Mencken Std Head (italic only, as supplied)
are self-hosted from `app/fonts/` via `next/font/local` (`app/fonts.ts`).

## SEO

- Titles, descriptions, canonical URLs and OG images per page: `lib/seo.ts` + each page's `metadata`
- Set `NEXT_PUBLIC_SITE_URL` if the live domain isn't https://theprive.network
- Favicon: `app/icon.png` (+ `app/apple-icon.png`)
- Unknown URLs show `app/not-found.tsx` with a button back to the homepage
- `/sitemap.xml` and `/robots.txt` are generated by `app/sitemap.ts` and `app/robots.ts` (add new pages to the sitemap list)
- Organisation structured data (name, address, LinkedIn/YouTube) is in `ORG_LD` in `lib/seo.ts`
- Old Framer addresses (`/home`, `/home/...`) redirect permanently in `next.config.ts`

## Shareable links

- `/?event=get-unstuck` opens that card's popup in the When carousel
- `/?session=oded-netzer` opens that session on the month calendar
- `/#calendar` scrolls to the calendar (the Calendar button uses this from other pages)

## Tracking (Google Tag Manager + Meta)

- Google Tag Manager (`GTM-PN4B367L`) loads on every page from `app/layout.tsx` via `@next/third-parties`.
  Add the Meta pixel and any other tags **inside GTM**, never in the site code, so nothing loads twice.
- Meta domain verification tag (`facebook-domain-verification`) is in the root `metadata` in `app/layout.tsx`.

## Request an invitation form

The **I am Interested** button in each event popup opens the on-site form in
`components/site/InvitationModal.tsx` (the carousel cards have no Register button; people open View Details first). It asks for name, email, phone, company (optional) and
notes (optional); the request is recorded against that event, with no date picker.

- Which events get the button: `register: true` on the event in `content/events.ts`.
  Events with `hideViewDetails` have no popup, so no button
- On a successful send it pushes to the GTM dataLayer:
  `{ event: "invitation_request_submitted", practice_id, practice_name }` (no personal details)
- Each request also carries the visitor's UTM tags / `fbclid` from the page they landed on, so it can be traced to its ad

**Where submissions go:** a Google Sheet, set with environment variables on the host (see `.env.example`):

- `INVITATION_WEBHOOK_URL` + `INVITATION_WEBHOOK_SECRET`: the Google Apps Script in `scripts/invitation-sheet.gs`
  adds each request to an "All requests" tab, a tab per event and a per-event count on a "Summary" tab
  (setup steps at the top of that file). The Apply for Membership form (`/apply-for-membership`) uses the same
  script and sheet, and goes to its own "Apply for Membership" tab with its own columns.

Without them, the form works in `npm run dev` (requests are printed in the terminal) but **refuses requests on the
live site** and asks the visitor to email instead, so nothing is silently lost.
